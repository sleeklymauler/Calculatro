# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Windows-only project (paths rely on `%APPDATA%`). Use the venv interpreter:

- Setup: `python -m venv .venv; .venv\Scripts\pip install -e ".[dev]"`
- All tests: `.venv\Scripts\python -m pytest`
- Single test: `.venv\Scripts\python -m pytest tests/test_engine.py::test_name`
- Performance: `.venv\Scripts\python tests\perf\benchmark.py` (timings; `-k` filters, `--compare tests\perf\baseline.json`; the "Best discard" scenarios time the search button), and `.venv\Scripts\python -m pytest -m perf` (exact results against the committed `tests/perf/expected.json`, written by `benchmark.py --update-expected`; timings against the git-ignored, per-machine `tests/perf/baseline.json`, measured by `benchmark.py --save tests\perf\baseline.json`, without which a run stops at collection; skipped by a plain `pytest`, which instead checks the exact results of all but the scenarios in `tests/perf/test_expected.py`'s `SLOW`, without timings). See `docs/performance/README.md`.
- Run: the mod starts the app with the game (see below). By hand: `.venv\Scripts\python -m calculatro watch` (`--file` overrides the state file path), which shows the console output. What to calculate is set in game, with the panel's target editor.
- Install the mod into the game: `pwsh scripts/install_mod.ps1` (copies `mod/Calculatro` to `%AppData%\Balatro\Mods`; requires the Lovely injector DLL next to `Balatro.exe`). Re-run after any change to the Lua. It also writes the venv's `pythonw.exe` path to the installed mod's `launch.txt` (skip with `-NoAutoStart`): on its first frame the mod starts `pythonw -m calculatro watch --game-pid <pid>` through LuaJIT's FFI (`ShellExecuteW`; `os.execute` would flash a console). With `--game-pid` the app exits when the game does (`process.exited`), exits at once if another instance holds the `Local\Calculatro` mutex (`process.claim_instance`; every `watch` claims it; one started by hand beside another only prints, leaving the odds file to the first, since two writers would clash over it), and logs errors to `%AppData%\Balatro\calculatro.log`.
- Release: `powershell -ExecutionPolicy Bypass -File scripts\build_release.ps1` (5.1 or 7) builds `dist\Calculatro-<version>-windows.zip` for players (not `Calculatro-<version>.zip`, the name of the "Source code" zip GitHub adds to every release): the mod plus a pinned, hash-checked embeddable Python (`$PythonVersion`/`$PythonSha256`) with the `calculatro` package in the mod's `python` folder, which the mod runs when there's no `launch.txt` (`Calculatro.launch_command`). The versions in `pyproject.toml` and `lovely.toml` must match (and `-Tag`, if given). Pushing a `v*` tag runs `.github/workflows/release.yml`: tests, build, and a draft GitHub release with the zip.
- Lint: `.venv\Scripts\ruff check .` (`--fix` applies the safe fixes, including import sorting). Configured in `pyproject.toml` (`[tool.ruff]`); there's no formatter. The Lua's globals are checked by a test (see Tests).

No runtime dependencies; `pytest`, `lupa` and `ruff` are dev-only.

## Architecture

Two halves connected by two JSON files:

1. **Lovely mod** (`mod/Calculatro/`): `lovely.toml` registers `calculatro.lua` as a module, patches `Game:update` to call it every frame, and `Controller:key_press_update` for the panel's hotkey (`C`). The module throttles itself to ~5 snapshots/sec, serializes Balatro's global `G` with its own JSON encoder, and writes `%AppData%\Balatro\calculatro_state.json` only when the output changes (write to `.tmp`, remove, rename — the Python reader tolerates the file briefly missing). Each written snapshot gets an `id` (`<session>:<seq>`).
2. **Python app** (`calculatro/`): `source.py` polls the file's mtime/size → `state.py` parses it into frozen `GameState`/`Card` dataclasses → `engine.py` computes exact odds → `report.py` collects them into a `Report` → `__main__.py` formats it for the console and `overlay.py` for the mod. `__main__.run_watch` runs the odds in a `worker.Job` (daemon thread): each new state cancels the running job (the engine checks the `cancel` Event and raises `engine.Cancelled`), and odds slower than ~0.25 s print the summary first with "Calculating odds..." and follow when ready. Keep new slow code paths cancellable. A job that fails (anything but `Cancelled`) doesn't stop the app: `run_watch` logs the traceback on stderr (once while the same one repeats) and answers as if there were nothing to show, odds without values (`overlay.odds(state, None)`) or a search with no options, so the panel isn't left "Calculating..." or "Searching...". Any other error on `run_watch`'s main loop (a bad state that got past the parser, the console failing) is logged the same way and the loop carries on, so the next state is still answered. Odds are only calculated while the hand is `settled` (`SELECTING_HAND`, or no state given): while cards are dealt, a played hand scores or a pack is open, the hand changes card by card, so the app only answers `pending` and the panel keeps the last odds greyed. Best-discard searches run in a second job (see 5.), cancelled only when `search_basis` changes.
3. **Odds panel**: the app answers each snapshot in `calculatro_odds.json` (same directory, atomic `os.replace`) — first `{id, pending: true}`, then the odds, echoing the snapshot's `id`. `overlay.write` returns False rather than raising if the file stays locked; `run_watch` then resends the latest payload every `RETRY` seconds until it's written or a newer one replaces it. The mod reads it ~20×/sec with a small JSON decoder and draws a Balatro `UIBox` right-aligned above `G.deck` and high enough to clear the raised hand (`panel_lift`), rebuilt only when its layout changes (`layout_key`: the model without the odds values, their staleness and the title row's message); otherwise the value text nodes (tagged `config.calculatro_value`) get the new text and colour in place and the box is laid out again (`update_values`, the game's `recalculate`; the new values come from a definition built without the suit icons' sprites, `values_definition`, since the game keeps every `Sprite` made until it's removed), since a rebuild costs the game tens of milliseconds. A rebuild reuses the rows per column fitted before for that layout and room (`Calculatro.fits`), and boxes are removed with `remove_box`, which hands the game empty object lists for the removal (it unregisters each element with a linear search) and then drops the removed objects in one pass. Every box the mod builds (and each hover popup) is followed by `register_once`: the game registers an element in `G.MOVEABLES`/`G.STAGE_OBJECTS` each time it lays it out, twice inside a `maxw`/`maxh` cell whose contents are shrunk, and unregisters it once on removal, so without it every rebuilt panel leaked until the heap passed the game's 300 MB ceiling (`nuGC`), past which it collects garbage every frame and runs at a few fps. Its height is capped by the consumables' count label (`max_panel_height`, measured from the label's own UIBox, `G.consumeables.children.area_uibox`, once it exists): target hands and card queries are separate sections, each filling columns of its own under its own header ("Hands  Keep  Discard" / "In hand  Discard"), so "Keep" never sits over cards. It's built with each section in one column, then one fewer row per column, and so on until it fits, so each column is filled as far as fits before the next starts (6 rows in game), growing leftwards over the play area (empty while selecting). At most 3 columns (`max_columns`; a 4th reaches the HUD sidebar) of 6 rows fit, so the mod won't track targets + card queries needing more (`Calculatro.columns_needed`, mirrored by `overlay.columns_needed`, `ROWS_PER_COLUMN`, `MAX_COLUMNS`, which the app also enforces; "Any target" adds a hand row when there are several targets); keep both in step if the panel's sizes change. Card rows have no Keep value (with a full hand and nothing face down it's 0% or 100%), so their names span the hands' name and Keep widths (`CARD_NAME_W`, as in the editor's list) less the pencil's (`EDIT_W`, see 4.), since text wider than its cell is shrunk; their Discard value is still green/red against keeping (`trend`). Card query labels too long even for that are cut short instead (`Calculatro.fit_label`, measured with the game's font: the name loses letters, never its suit icons or count), and every card name, in the odds and the editor's list, shows a popup while hovered (`card_name_cell`, `hover_popups`: the game's `h_popup`, built anew on each hover) in the panel's colours (light text on `inset_colour`, deeper shadows) with the full label and what it means (`about`, written by `builder_about` when the query is added and kept with it; queries added before that have none). Mouse only for now. The Keep→Discard arrow (`arrow`) is drawn as boxes the size of the font's pixels (`FONT_PX`, 0.02 units at the panel's text scale), since a text `->` is too wide for its gap and would be shrunk. Target rows split the gap and the Discard cell differently from the header: `DISCARD_VALUE_W` just fits the widest value (">99.9%"), and the arrow sits in the rest (`ARROW_CELL_W`), midway between the Keep value and a typical one ("88.3%"). The panel draws its own shadows (`deepen_shadows`, on the built UIBox's elements): the game drops text shadows 0.5 parallax units away, nearly invisible on the dark inset, and box shadows 1.5. Text and the arrow both use `SHADOW_DEPTH` instead. The mock `UIBox` has no `UIRoot`, so this isn't covered by the tests. The message ("Calculating...", "Waiting for app") must never change the panel's size, or the columns would flip as it comes and goes: beside the odds it sits on the title row in a space kept for it whether or not there's one (`MESSAGE_W`, so messages there must be short); only with nothing tracked ("Nothing tracked") does it get a row of its own. There's deliberately no hint to select cards, and no "No discards left" (the game shows that). The frame takes the boss's colours like the HUD, but the inset behind the odds is always dark (`inset_colour`, what `BOSS_MAIN` is outside boss blinds): `BOSS_MAIN` is the raw boss colour, too light for the text on bosses like The Club and the same hue as the green/red values on others. Header/footer text uses solid `G.C.JOKER_GREY` and stale values `G.C.UI.BACKGROUND_INACTIVE`, since the translucent `TEXT_INACTIVE` disappears on some boss colours. Long hand names are shortened in `SHORT_NAMES` (Lua). Odds whose `id` isn't the latest snapshot's are still shown, greyed with "Calculating..." after 0.3 s; with no reply at all for 2 s it says it's waiting for the app; odds from another game session are ignored, and so are those for snapshots taken before the round began (`Calculatro.check_round`, on `G.GAME.round`, which the game increments as a blind is selected), so the first hand of a blind shows '-' while it's dealt rather than the last round's odds. The panel only exists in a blind (`Calculatro.in_blind`: `SELECTING_HAND`/`DRAW_TO_HAND`, or `PLAY_TAROT` interrupting one, and no `G.OVERLAY_MENU`); it's hidden while a played hand scores (`HAND_PLAYED`), since the played cards reach it. Rebuilds are animated (`Calculatro.animate`, run on the final box in `refresh_panel`): elements tagged `config.calculatro_anim` (the frame, body, inset, title row, each odds row by key, headers by section and column, the editor's rows) are matched by key between the old and new box; matched ones move and resize from where the old box drew them (`drawn_layout`, so a rebuild mid-animation carries on, and a move whose destination is unchanged, as when only the odds change, isn't restarted), new ones pop in afterwards, slightly staggered, and a panel that appears pops in whole. Untagged elements follow the nearest tagged one around them; removed ones vanish. It's done only while drawing (the box's `draw` is replaced), by adjusting each element's `VT` and putting it back after, so layout, collision and buttons see only the final places. Give new panel rows a unique `calculatro_anim` key, or they'll move with their column/inset instead of gliding. It's off with the game's Reduced Motion setting. `tests/test_animation.py` runs it on hand-built element trees. The UI must work on standard 16:9 screens as well as ultrawide: Balatro lays everything out in a fixed 20×11.5-unit room scaled to the window, so place UI relative to game objects in those units, never in pixels or relative to the window edges. Python sends display-ready values (`overlay.percent`), but the mod names the rows itself, since it owns what's tracked and shows rows before the app has answered: each odds row carries a `key`, the hand's name ("Three of a Kind", "Any target") or the card query's text, and the panel shows a row per tracked target with the odds for its key ('-' until there are some). Balatro's font (m6x11) has no suit symbols, arrows or ≤/≥, so panel text must be ASCII (draw anything else, like the arrow and the `x` (`glyph`)), except for ♠♥♣♦ in card query labels (e.g. "Q♠: 1+"): the mod's `name_label` draws those as the game's own suit icons, sprites from the `ui_1` atlas (`ui_2` with the colourblind option) at `{x, y = 1}`, as in the View Deck screen, each on a small white tile so the black suits show on the dark inset.

4. **Targets** are set in game and owned by the mod: `Calculatro.tracked()` keeps `{hands = {names in HANDS order}, cards = {{query, label}}}` on `G.GAME.calculatro`, so the game saves them with the run and a new run starts empty (hand names not in `HANDS`, like Royal Flush from older saves, are dropped); the snapshot sends them as `tracked` (`GameState.tracked_hands`/`tracked_cards`), and `__main__.tracked` validates them (unknown or repeated ones and any past the column limit are skipped). Each odds row has an `x` to stop tracking it (not "Any target"); card query rows, in the odds and the editor's list, also have a gold pencil (`edit_cell`, `PENCIL`) between the search button and the `x`, which opens the Cards tab on that query's page with the builder set to make it (`Calculatro.edit`; `Calculatro.builder_for` reads a query back into the builder's choices, and only accepts one `builder_query` gives back, so the pencil is inert for queries the builder didn't make). While editing (`editor.editing`, outlined pencil), Add is Save (`save_card`, `Calculatro.replace_card`: in the edited one's place, inert until the query changes or if it's tracked already) and editing stops after; the edited one's pencil stops editing, keeping the builder's choices. The `+` after the title opens the **target editor** (`editor_model`/`editor_definition`) on the tab last shown (`Calculatro.editor_tab`, Hands at first), which replaces the odds in the same frame until Done: a Hands tab of 11 toggles (no Royal Flush: the game scores it as a Straight Flush) and a Cards tab whose builder (`OPTIONS`, `Calculatro.builder`) builds a query string `cards.parse_query` accepts plus its label (`builder_query`, matching how the app names queries; Python stays the only parser), and the tracked queries 5 to a page. The builder has a count (comparison cycle and number, with a second number for "between"), 13 rank chips under a preset cycle (`OPTIONS.preset`; the chips show "Custom" when they match none; presets with a `query`, like Face and Even, are sent by name so the app matches them as the game does), 4 suit chips (all on by default; turning off the last turns them all back on) and a special with a `not` toggle. Under Stone (not negated) the rank cycle and chips show any and are inert, since Stone Cards have no rank or suit (`stone_only`; the choices are kept for other specials). Chips are ORed; none or all of them means any. `+`, toggles and Add are greyed and inert when another wouldn't fit. Buttons are `C` nodes with `button = 'calculatro_button'` (`G.FUNCS`, set each frame) and the action in `config.calculatro_action`, dispatched by `Calculatro.act`; the panel UIBox has `can_collide = true` for them. They don't shake the screen: `steady_buttons` gives each a `click` that undoes the `G.ROOM.jiggle` the game's `UIElement:click` adds (the click sound stays). Buttons need a box that isn't replaced while they're used, so the editor is rebuilt only when its own model changes (its buttons), never by odds; it closes when the panel goes away. The editor's tabs take the header's place, but its toggles and option cycles have `TEXT_PAD` above and below their text (`padded`), since m6x11's descenders hang below a text node's box; that makes it taller than the odds panel with 6-row columns, so `refresh_panel` lowers it by whatever doesn't fit under the consumables, into the room kept for raised cards. Both tabs are the same size: `EDITOR_W` is the Cards tab's width worked out from its cells and paddings, and both are given the Cards tab's height (`EDITOR_H`: five builder rows and Add, from `TEXT_H`, a text node's exact height in the game's layout). Add and the page cycle share a row under the builder and the list, so Add takes the width the page cycle leaves (`ADD_W`; its label is cut to fit with `fit_label`, like the list's names, but has no popup: the builder above it shows every choice) and the page cycle doesn't move between pages.
5. **Best discard**: each odds row (including "Any target" and card queries) has a green search button (`search_cell`, a `MAGNIFIER` `glyph`, in a `SEARCH_W` column before the `x`). Clicking it sends `search = {key, nonce}` with the next snapshot (`Calculatro.request`, sent with every snapshot; the app acts on each nonce once) and remembers the hand's card objects (`Calculatro.searching`); the button is dimmed and inert and the title row says "Searching..." until the reply. `run_watch` runs `search.best_discards` for the row's target, or `search.best_card_discards` for a card query (`__main__.search_target`, which looks hands up first: no query's text is a hand's name, so the request has no kind; `find_best`), in a job of its own, cancelled only when the hand, deck, jokers, blind or discards change (`search_basis` ignores the selection, so the search's own selection doesn't cancel it) or the row's target does (`search_target`: "Any target"'s hands), and puts its result (`overlay.search`: every tied option as 0-based hand indices, best first; no options for an untracked key) on every payload until then. A cancelled search runs again if the snapshot still asks for it: the mod sends the request only until it's answered or its hand is gone (`check_search`, run before the snapshot), so it's never left "Searching..." by a change it can't see in the hand's card objects (a Tarot changing a card in place, a joker sold). Python's `search_basis` is the one definition of a result still standing: the mod drops its options (`Calculatro.found`, kept with their nonce) once a payload comes without them or with others (`receive_search`), and the button then asks again. The mod applies a reply only if its nonce is the one asked for and the hand is still the same card objects in the same order (`receive_search`), selecting the first option (`Calculatro.select`: `unhighlight_all`, which leaves Cerulean Bell's forced card selected, then `add_to_highlighted` with one click sound). A reply that arrives while it can't search (a Tarot choosing its cards) is kept with `index = 0` and selects nothing; the button's next click selects its first option. Clicking again cycles through the options (`Calculatro.found`) while the hand is the same and it can search: the next if the selection is still the last one made, else the first. The title row shows "i/n" with several options and "Keep hand" when keeping is the only best; "Calculating..." and "Waiting for app" take priority. Buttons are inert outside `SELECTING_HAND`, or with no way left to throw cards away before the last hand (`search.can_redraw`/`Calculatro.can_search`: a discard, or a hand played as one with another left after it). There's no cap on tied options for now (a hand that already has a Pair ties on dozens of discards); revisit if it's a nuisance in play.

### Contract between the halves

- `SCHEMA` in `state.py` must match `schema` in `calculatro.lua`, and `overlay.SCHEMA` must match `odds_schema`; bump both sides when changing either JSON shape. A snapshot of another schema (the previous version's file at startup, or a mod not reinstalled after an update) raises `state.SchemaMismatch`, which `FileStateSource.poll` skips with one message on stderr until the file changes, rather than stopping the app; so does one of the right schema that can't be decoded (invalid UTF-8, not JSON) or whose fields have the wrong shapes (`state.MalformedState`, from `FileStateSource.read` or `GameState.from_json`; only shapes are checked, not ranges, and of the scalars only those that must be text, since the encoder can write the game's numbers as floats or `null`; its message isn't repeated while the same error recurs). The odds file never contains `null` (the Lua decoder doesn't support it). The snapshot also sends `select_limit` (`G.hand.config.highlighted_limit`) and the latest `search` request; the odds file's `search` answers it (see 5.).
- Information hiding is deliberate: the undrawn deck and the face-down cards, in hand or discarded (the game doesn't turn a discarded face-down card up; View Deck still counts it as unplayed), go out together as one **sorted multiset**, `unseen` (`unseen_pool`), so neither draw order nor which cards are face down or were discarded face down leaks (not even by comparing snapshots as a card is drawn face down), and the jokers sorted too (Amber Acorn shuffles them face down). Face-down cards in hand and in the discard pile are exported as `{hidden: true}`; the deck's size is `len(unseen)` less their number (`GameState.deck_size`, `hidden`, `discarded_hidden`), and under The Mark the discarded ones count as face cards too. The engine draws kept face-down cards from `unseen` like the new cards, except that under The Mark (`GameState.mark`) they're known to be face cards, so they're drawn from the unseen face cards (`engine._mark_split`). Don't add anything to the export that reveals information a player couldn't see.
- Empty Lua tables can arrive as `{}` rather than `[]`; the encoder tags arrays with an `ARRAY` metatable, and `state._cards` also handles it.
- Card fields mirror Balatro internals: `rank_id` 2..14 (Ace=14), `enhancement` is the center key (`m_stone`, `m_wild`, `c_base`, ...).

### Probability model

- `hands.py` expresses each poker-hand target as OR-of-patterns, each pattern an AND of `Requirement`s ("at least `need` cards whose class key is in `keys`"). Requirements are usually disjoint; they may overlap (a card then counts towards each). Class keys are `(rank_id, suit)` with suit `"Wild"` for wild cards; with Smeared, Diamonds are keyed as Hearts and Clubs as Spades, and flush-type patterns use only those two suits (`flush_suits`). Containment follows Balatro's rules (Straight Flush contains Straight; Four of a Kind does *not* contain Two Pair). Stone/hidden cards have no key; a debuffed Wild loses wildness. `combine()` builds an "any of these targets" Target, pruning implied patterns.
- `engine.probability()` is exact (`Fraction`), not Monte Carlo: pool cards are merged into classes by which requirements they count toward, then enumerated class-by-class hypergeometrically with early-accept (satisfied ⇒ binomial of remaining), pruning of unreachable patterns, and memoization on a canonical key of what the live patterns still lack. Only patterns touched by the current class are re-assessed. Targets with patterns of several suits are split by suit with inclusion-exclusion (`_union_by_suit`), so each search tracks one or two suits instead of all four; this is skipped when an unseen card is Wild, which links the suits again. Terms that are the same up to relabelling suits (same ranks kept and unseen, e.g. a fresh deck in The House) are computed once. See the module docstring and `docs/performance/` (design notes, per-joker notes, benchmark tables) before modifying, and add benchmark scenarios to `tests/perf/scenarios.py` for new joker rules.
- How a pattern is stated drives the search's size: it memoizes on what each live pattern still needs, so prefer requirements that leave little to remember. Four Fingers' Straight Flush says "a suited card of another rank" rather than "4 suited cards in all", so the search tracks whether a suit has shown up rather than its count, and runs sharing their 3 suited ranks are one pattern ("any card that completes the run"). Classes are swept rank by rank (Wild Cards first in their rank), or suit by suit when no requirement spans several suits; the order patterns are listed in doesn't matter. A pattern joins the search at its first single-rank class; draws before that towards its other requirements are deferred counts in the memo key. In the search, a pattern's state is an interned "part" (unmet requirements as bitmask of remaining classes + deficit), moved past each class by a cached transition; parts implied by a one-card part are dropped from the state.
- `cards.py` parses card queries (`"2+ queens"`, `"at most 1 spade"`, `"QS"`, `"1-3 even of red suits"`, `"not sealed"`; the editor writes them as `"at least 2 lucky queen of spades"`, `"between 1 and 3 not sealed queen or king of hearts or diamonds"`) into `CardQuery` (`text` keeps what was parsed, the odds' key); like targets (`engine.evaluate_discard`), these count the final hand, kept cards and draw (`engine.evaluate_cards`: the kept matches plus a hypergeometric count over the face-down kept cards and the draw, with The Mark's split and an average over The Hook's picks). A single query never goes through the pattern search. `search.best_card_discards` groups hand cards only by whether they match (face-down ones apart), so it's a handful of evaluations.
- Joker rules (Four Fingers, Shortcut, Smeared, Pareidolia) live in `rules.Rules`, built by `GameState.rules` from non-debuffed jokers. Pareidolia affects only face-card queries (`cards._is_face`: every non-debuffed card, Stone included), never hand patterns. A `Target` only names hand types; `Target.patterns(rules)` builds (and caches) the patterns for a ruleset, and `card_key`, `probability`, `count_probability` and `CardFilter.test` all take the `Rules`.
- The "discard" scenario uses the cards currently highlighted in game (`GameState.selected`), except on the last hand with no discards left (`search.can_redraw` false): nothing is drawn after it, so `build_report` gives no discard odds and the panel shows '-'.
- `search.best_discards` compares keeping the hand with every discard (or hand played as one, `can_redraw`) of up to `select_limit` cards (always including Cerulean Bell's forced card), for this discard and draw only, using `evaluate_discard`. It enumerates counts per group of hand cards the target can't tell apart (`_groups`: by which requirements a card's key counts towards, face-down cards together; by class under Cerulean Bell, whose random forced card makes the class matter), then expands the best counts into every distinct tied discard (identical cards collapsed, leftmost first), ordered fewest cards, then lowest ranks thrown away, then leftmost. `tests/test_search.py` checks it against trying every subset. It works out each distinct discard once (`_relabelled`: ranks or suits the target can't tell apart are dropped, and relabelled when the patterns are symmetric), bounds "Any target" by its hands' own odds so few need the exact union, and passes one `engine.Reuse` to every `evaluate_discard` so the engine shares its pool-dependent setup (`_layout`), results and memo between discards (`_search`'s `signature`); see `docs/performance/best-discard.md`. Four Fingers + Shortcut with Straight Flush still takes seconds.
- Boss rules: The Serpent's draws (`GameState.serpent`), The Mark's face-down face cards (`GameState.mark`, `engine._mark_split`) Cerulean Bell's forced card (`GameState.bell`/`forced`, from the hand cards' exported `forced` flag; `hands.forced_patterns`, `engine._bell_after_draw`) The Hook's 2 random cards thrown away after a play, which applies when the selection has to be played for want of discards (`GameState.hook`, `engine._hooked`/`_after_hook`), and Crimson Heart's joker swap after such a play, which changes the rules the final hand is judged under (`GameState.crimson`, `engine.rules_after`, `search._rule_sets`; run-out Perishables, which it can't swap, are exported as `perished`). The Eye's and The Mouth's banned hands don't change the odds: the mod strikes those targets out in the panel itself (`Calculatro.banned_hands`, read from `G.GAME.blind`). `docs/blinds.md` has the details; a new boss rule must check `blind_disabled` like these.
- DNA: a lone card played as the round's first hand (no discards left, so `evaluate_discard` predicts across a play) comes back as `dna_copies` known cards instead of being replaced by a draw (`engine._dna_copies`), so the odds normally equal Keep's. The mod counts the copies, following Blueprint and Brainstorm chains (`jokers` hides the order; with a joker face down, only DNA itself counts). See `docs/jokers.md`.
- `docs/jokers.md` is the joker reference (all 150, with internal keys and the exact game rules for Four Fingers / Shortcut / Smeared / Pareidolia). Use it instead of the wiki, which it corrects from the game's code. `docs/blinds.md` is the same for all 30 blinds (exported as `blind` = `G.GAME.blind.name`, plus `blind_disabled`): which bosses the engine models, which arrive through the exported state, and which it gets wrong.

### Tests

`tests/test_state.py` runs the real `calculatro.lua` inside `lupa` against a mocked `G` and `love.filesystem`, then parses the written file — so mod changes are testable without the game. Extend `MOCK_G` there when exporting new game fields. `MOCK_G` also mocks `UIBox` (recording every box in `BOXES`); `tests/test_overlay.py` checks the panel's text and colours end to end. The game runs LuaJIT (Lua 5.1) while `lupa.LuaRuntime` is newer Lua, so avoid 5.2+ features: the `lua` fixture runs every Lua test in both (`[lua]` and `[luajit]`; each runtime has its own `LuaError`). pytest's faulthandler is off (`addopts`), since LuaJIT's errors are Windows exceptions it would report by the thousand. `tests/test_lua_globals.py` lints the mod's globals from its LuaJIT bytecode: it may assign none, and read only LuaJIT's and the game's (`GAME_GLOBALS`; add to it when the mod uses another game global).
